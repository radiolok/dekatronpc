# Тезисы для нового видео (что сделано после опубликованных роликов)

Источники: `history.md`, `TRS.md` (v0.53), `doc/`, `git log` и транскрипции плейлиста (23 файла). Транскрипции прочитаны выборочно (поиск по ключевым словам плюс ролики 8, 13, 19, 3, 6, 10), распознавание речи шумное. Год стрима №8 (июнь) выведен из ролика №6 (август 2024) и не подтверждён.

Точка отсчёта: последние ролики про инженерную часть — стрим «Ламповый компьютер будет?» (№8: 1244 лампы по синтезу на 7 июня, 1 МГц, 200 тыс. инстр/с на эмуляторе, загрузчик «ещё не реализован») и «Ламповый компьютер ожил! Но пока в VR..» (№6, август 2024). Всё ниже — после них (коммиты с 2026-09-10 и позже, кроме отмеченного).

## 1. Архитектура и набор команд
1. **ISA16**: один 4-битный набор на 16 кодов, без режимов. BF 0x0–0xA, `LD` (SOT/EOT), `CLRA`, `MemLock` (копирование `>P<`), скобки `{ }` по AP. Выбран после эксперимента на 720 синтезах (−66,5 ламп).
2. **Загрузчик в железе**: `0<{0<}` в верхней декаде 99990–99999, она защищена от записи. Hard/Soft Reset, EOT запускает Soft Reset. Программа сама стирает память и грузится с адреса 0 (в №8 было «ПЗУ на 100 ячеек, пока не реализовано»).
3. **MemLock — единственный флаг владения ячейкой**: убран dirty, память хранит последнюю тронутую ячейку, свой копии у ApLine нет. COUT всегда печатает счётчик данных.
4. **Предвыборка** следующего опкода: helloworld 5540 → 4184 такта (CPI 13,8 → ~10). pi.bfk — 2,74 млн тактов.
5. **Счётчики**: Loop 0–99, переполнение — аппаратная ошибка, замораживает IpLine до сброса. Данные 0–255, AP заворачивается 0↔99999 (предел 29999 — вопрос OPEN-001). Шины значений BCD с активным низким уровнем (TC-O3): экономия лампочек на инверторах.
6. **Банковая память** (дерево банков, адреса — BCD-тетрады без двоичной арифметики, A..F дают ошибку).

## 2. Проверка: от эмулятора к доказательной базе
7. **TRS.md** с ID требований и статусами (v0.53), все решения и отказы записаны (в видео стоит показать «книгу отвергнутого»: реле в логике, анодный повторитель как AND, снижение анодного до 120 В).
8. **Золотая модель** `dpcrun` (C++) сверяется с RTL шаг в шаг: pi.bfk — 221 386 шагов совпали, вывод 3.141. Проверка заодно нашла тесты, которые «проходили без проверки».
9. **Симуляция нетлиста с реальными задержками ламп** (`synth_sim.sh -t`): helloworld и program.bfk идут на задержках из SPICE. Эмулятор заменён на модель, которая ближе к железу.
10. **Веб-симулятор в браузере** (JS-порт dpcrun, GitHub Pages): пульт, декатроны, SOT/EOT. Можно показать зрителям без платы.
11. **CI**: Icarus, Verilator, Yosys, cocotb 34/34, Quartus.

## 3. Декатрон как физический объект
12. **DekatronCounter переписан**: любая операция завершается в такте приёма, у лампы нет valid/busy, ready берётся из известных длительностей. Убраны FSM, защёлки, сигнал Valid.
13. **Направляющие импульсы должны перекрываться** (статья Harwell Dekatron Computer, 1951; Phase2 стартует от спада Phase1). Положение при включении случайное — лечится линией сброса.
14. **Физика по Липкину и Яблонскому**: смещение на направляющих, «стоячий» катод, анодный резистор у лампы. Решения по таймингам: спад 1000 нс, положительное смещение направляющих.
15. **А110**: справочный лист оцифрован (зажигание 175–205 В, счёт < 1 МГц, управляющий импульс 38 В), поведенческая модель в SPICE совпала с RTL на 14/14 операций. Реальные тайминги всё ещё нужно мерить (OPEN-013/014).
16. **Модуль декатрона**: запись через 6Н16Б по каждому катоду, чтение через диоды 6Х7Б, ключи направляющих на отдельных платах. Раскладка: IP 18 ламп/2 платы, Loop 7/1, AP 16/1–2, Data 22/2. Старший разряд Data читает/пишет только катоды 0–2 (−12 ламп).

## 4. Ламповые ячейки (самое большое, чего в роликах нет)
17. **Библиотека ячеек, рассчитанных в SPICE и нарисованных в KiCad**: NOR2/NOR3/NOR4, NOT, NAND2 на 6Ж2Б, AOI21/AOI22/AOI211, RS-защёлка, D-защёлка, DFF (в т. ч. со сбросом через 6Х7Б), пульсовый DFF 3,5 лампы, KEYDB (антидребезг ключа). У каждой своя папка с чертежом, тестбенчем и страницей.
18. **Два семейства уровней**: HV (+150/+50 В на анодах), LV (+10/−20 В на сетках). Делители вынесены в ячейки, анодные дроссели ускоряют фронт на 20–25 % (по Бонч-Бруевичу).
19. **Метод проектирования ячеек** (`doc/cell_design_method.md`) и ловушки (Миллер, хвост g3, перекрёстные наводки). Измерен реальный Cg3a = 1,8 пФ на 6Ж2Б-В.
20. **Оцифровка справочников** (6Н16Б, 6Ж2Б, 6Х7Б, А110) своим инструментом `digitize.py`, плюс инструкция, чтобы то же делала небольшая локальная модель.
21. **Лампы собираются из библиотечных ячеек**: синтез ведётся по liberty-файлу ламповых ячеек, диодные вентили и повторители запрещены (dont_use), отсюда честный подсчёт.

## 5. Число ламп и частота
22. **Путь счётчика**: честный поток дал около 2636 ламп на три блока, дальше цепочка шагов (area-ABC, перепись FSM у Ap/Ip/MachineCtrl, binary-кодирование, одна защёлка на декаду, NOR3/AOI211, снятие rst_n с триггеров, шаги TC-N1..N3, O9) до **~1069 ламп (среднее по 4 зерням) + 15 декатронов**. Бюджет был 1500, потом 1200; следующий порог — меньше 1000. Все решения и отказы зафиксированы в `doc/tube_count_*.md`.
23. **Цена команд**: EOT −26,5 лампы, `[-]`, SOT и прочие измерены по очереди. Это основание для ISA16.
24. **Частота**: вместо 1 МГц из №8 принято Clk = 100 кГц (hsClk = 10×Clk). Статический анализ по SPICE-задержкам: минимальный период ≈ 8–9 мкс, 100 кГц проходит с запасом ~2 мкс. 1 МГц для логики на этих ячейках не достижим (OPEN-014 остаётся для самого декатрона).
25. **Мощность из нетлиста** (REQ-VER-035): ток каждой ячейки по состояниям пинов, интегрирование VCD.
26. **Гонки на границах**: внешние источники меняют данные только на спаде такта, ключи панели проходят через синхронизаторы на DFFP.

## 6. Память и ввод-вывод
27. **Ферритовая память КП128/17-М70**: паспорт и распиновка оцифрованы, структура двух блоков 12/8 (4 инструкции + чётность в слове программы), эскизы ключей X/Y, каналов записи/чтения (не моделировались). До последнего момента роль памяти играет эмулятор на FPGA.
28. **Эмулятор ↔ DekatronPC**: интерфейс заморожен приложением B TRS, RX Valid/Ready (REQ-UART-008).

## 7. Стенд питания (рассказ про отладку)
29. Блок питания стенда (TL494, три канала): ревью схемы, исправленные ошибки, «сверчок» на 120 В (пропуск импульсов, лечится резистором в светодиоде оптрона), потери на межобмоточной ёмкости бифилярной обмотки, канал 200 В — насыщение сердечника и «дрейф потока» (разбор по осциллограммам автора, **не закрыто**). Хорошо ложится на ролики №18 и №23.

## 8. Процесс и честные оговорки
30. Репозиторий с 2026-09-10 ведётся в связке с Claude Code (первый коммит так и назван). Показывать ли это — решение автора.
31. **Оговорки для зрителей**: новые ячейки проверены в SPICE и KiCad-тестбенчах, в железе подтверждено только малое (Cg3a, питание). В роликах №3–№6 экспериментальная ячейка на 76 лампах остаётся единственной собранной платформой по этим данным (в репозитории нет отчёта о новой сборке). Числа ламп зависят от зерна ABC на ±10.

## 9. Что поправить из старых утверждений
- «1 МГц» (№6, №8) → 100 кГц.
- «1244 / 1444 лампы» (№8) → ~1069 (другая ISA, другой поток, не прямое сравнение).
- «Загрузчика нет» (№8) → есть, в верхней декаде.
- Реле на переключателях панели (было в RTL с v0.10) → убраны в v0.43 (REQ-MOD-011 отклонено), переключатели идут в ламповую логику.
