# C++ golden model `dpcrun`: полный ISA

Модель лежит в сабмодуле `bfutils/dpcrun` (`dpcrun.h`, `dpcrun.cpp`), тесты — в `bfutils/dpcrun/test/test_dpcrun.cpp`, CI — `bfutils/.github/workflows/ci.yml`.

Итог:

- Модель переписана с нуля. Она поддерживает оба набора команд, MemLock с ленивым чтением, загрузку SOT/EOT, аппаратный и программный сбросы, переполнение счётчика циклов и защищённое от записи ПЗУ загрузчика.
- **По решению владельца проекта модель повторяет RTL как есть**, включая места, где RTL и TRS расходятся (§4). Исключение одно, это дефект COUT (§5.1).
- 53 модульных теста, 458 проверок, 1,5 с. Тесты гоняются в GitHub Actions репозитория bfutils (gcc и clang).
- Самопроверка по числам TRS: на `pi.bfk` модель насчитала **99 077** обращений к памяти данных — ровно столько, сколько замерено для RTL в TRS v0.7 §1. Расхождение IRET с цифрой 198 594 объяснено полностью (§3.4).
- При сверке найдено пять проблем в RTL и загрузчике (§5). Главная: `.` не запрашивает у `ApLine` чтение ячейки, и после `>` выводится значение предыдущей ячейки: Hello World печатается как `Hello WWrld!!`. TRS считает этот вопрос закрытым (OPEN-017).

## 1. Что было

Прежний `CppMachine`/`stepCpp()` интерпретировал **ASCII-текст** программы, а не опкоды (нарушение REQ-IPV2-005). Он знал только восемь символов Brainfuck и `0`. Не было Debug ISA, MemLock, SOT/EOT, сбросов и загрузчика. Промотка останавливалась не на парной скобке, а за ней, поэтому IRET не совпадал с RTL.

## 2. Интерфейс

```cpp
dpc::Config cfg;                 // apTop (OPEN-001), тумблеры RunOnHardRst, SoftRstOnEOT, EchoMode, Bell*
dpc::Machine m(cfg);
m.loadCode(dpc::assemble(src));  // загрузчик: текст -> опкоды, таблица generate_rom.py
m.setBootRom(dpc::assemble("DA0B<D{0B<D}BH"));
m.softReset(); m.run();          // панель: SoftRstKey, Run
dpc::Status s = m.step();        // одна инструкция = один проход S_DECODE
```

- `step()` возвращает `Ok`, `Halted` или `WaitInput`. `WaitInput` означает, что CIN или режим загрузки ждут ввода; после `pushInput()`/`pushInsn()` шаг повторяется.
- Наблюдаемое состояние: `ip()`, `ap()`, `loopCount()`, `dataCounter()`, `memLock()`, `dirty()`, `insnMode()`, `loading()`, `halted()`, `loopOverflow()`, `insn()`, `iret()`, `bells()`, `output()`.
- `txData()` — ровно то, что RTL выдаёт на `tx_data_bcd`: счётчик данных при MemLock, иначе выходной регистр памяти. После `>` регистр ещё хранит предыдущую ячейку. `cellValue()` — архитектурное значение текущей ячейки.
- Статистика `memReads()`/`memWrites()` повторяет обращения `ApLine` к памяти данных, включая `AP_TEST` перед скобками.
- Автономный запуск: `dpcrun -f prog.bfk [-b boot.bfk] [-B] [-a 99999] [-n max] [-s]`. Программа кладётся с адреса 0, за ней ставится HALT, затем Soft Reset и Run.

## 3. Семантика (по RTL)

### 3.1. Выборка и промотка (`IpLine`)

- IP указывает на **исполненную** инструкцию. Сдвиг выполняется при следующей выборке.
- После сброса, `CLRI` и останова первая выборка читает по текущему IP без инкремента (`ip_counted_q`).
- Решение о промотке принимается при следующей выборке по признаку `loop_val_zero`: в BF — ноль ячейки, в Debug — `AP == 0`. Детектор скобок один для обоих ISA.
- Промотка останавливается **на** парной скобке, и эта скобка затем декодируется как обычная инструкция (IRET +1).
- Счётчик вложенности: +1 за стартовую скобку и за каждую свою, −1 за ответную. Счётчик двухдекадный, 0–99 (`LOOP_SIZE = 100`, как `LOOP_DEKATRON_NUM = 2`). Инкремент со 99 — аппаратная ошибка (REQ-CNT-007). Как и в RTL (IpLine, `at_top`), она ловится ДО шага: инкремент не выдаётся, счётчик остаётся на 99 до CLRL или сброса, промотка прерывается, машина останавливается, звонок при `BellOnError`. Промотка, начатая со счётчиком на 99, переполняется сразу.
- Промотка **всегда завершается**. Память программ — кольцо: если своих скобок в нём не больше, чем ответных, счётчик доходит до нуля за один оборот. Иначе каждый оборот снова засчитывает стартовую скобку, и счётчик растёт до переполнения. Для одиночной `[` это примерно 10⁷ чтений (тест `unmatched_bracket_overflows`).
- Промотка идёт насквозь через ПЗУ загрузчика. `{`/`}` там имеют те же коды 0x6/0x7 и учитываются как скобки.

### 3.2. Данные (`ApLine`)

| Операция | Поведение |
|---|---|
| `+` `-` | без MemLock: чтение (если значения нет в регистре), затем шаг; MemLock и dirty ставятся |
| `>` `<` | если dirty — выгрузка в старую ячейку и снятие MemLock; шаг AP с переходом 29999 ↔ 0; ячейка не читается |
| `CLRA` | то же, что `>`, но AP → 0 |
| `CLRD`, `[-]` | счётчик → 0, MemLock и dirty ставятся (REQ-ML-009) |
| `,` | счётчик ← символ, MemLock и dirty; эхо при `EchoMode` |
| `.` | чтение, если значения нет ни в счётчике, ни в регистре; вывод (см. §5.1) |
| `LOAD` | счётчик ← ячейка; MemLock и dirty не меняются |
| `STORE` | ячейка ← счётчик, dirty снимается; MemLock не меняется |
| `CLRML` | выгрузка при dirty, снятие MemLock |
| `[` `]` в BF | `AP_TEST`: чтение, если значения нет под рукой |

Данные — 0..255 с переходом через 0. Сброс не выгружает грязный счётчик: его значение теряется, память сохраняется.

### 3.3. Управление (`MachineCtrl`)

- **HALT**: после останова IpLine сдвигает IP ещё на одну позицию, поэтому Run продолжает со следующей инструкции.
- **Hard Reset**: IP = 99900, AP/Data/Loop = 0, MemLock снят, Debug ISA. Машина стоит, если не включён `RunOnHardRst`. IRET сбрасывается только по `rst_n`.
- **Soft Reset**: всё в 0, BF ISA. Запуск — при `RunOnSoftRst`.
- **SOT** включает режим загрузки, ISA не меняется (OPEN-003, как в RTL). Опкоды пишутся с адреса после SOT, IP инкрементируется, каждый принятый опкод считается в IRET. Запись в банк загрузчика игнорируется.
- **EOT** распознаётся только в Debug ISA и в память не пишется. При `SoftRstOnEOT` выполняется Soft Reset, иначе останов. Вне загрузки EOT — NOP.
- **ISA0/ISA1** во время загрузки действуют и **записываются** в память.
- **BELL** считается событием `bells()`/`onBell` (OPEN-007 открыт).
- Все 32 комбинации `{mode, opcode}` декодируются. Резервный 0x3 Debug и EOT вне загрузки — NOP.

### 3.4. IRET на `pi.bfk`

TRS v0.7 приводит 198 594 инструкции — это счёт чистого Brainfuck. Модель насчитывает 221 386:

```
198 594  инструкций Brainfuck
+ 5 715  парных ']' после пропуска '['
+17 076  парных '[' после возврата по ']'
+     1  завершающий HALT
= 221 386
```

Каждая промотка добавляет декодирование парной скобки. Так работает RTL, и на эту величину должно рассчитываться пошаговое сравнение.

## 4. Где модель следует RTL, а не TRS

Решение владельца проекта (2026-09-27): модель повторяет RTL. Эти места отмечены в коде комментариями `RTL:` и закреплены тестами. Если RTL исправят, тест и модель меняются вместе.

| № | RTL | TRS | Тест |
|---|---|---|---|
| 1 | `CLRI` сбрасывает только IP, MemLock не трогает | REQ-ISA-DEBUG-004, REQ-ML-006: сбрасывает и MemLock | `clri_keeps_memlock` |
| 2 | `CLRA`, `>`, `<` снимают MemLock только вместе с выгрузкой грязного счётчика | REQ-ML-005/007: MemLock снимается | `clra_after_store_keeps_lock` |
| 3 | После `STORE` (MemLock = 1, dirty = 0) блокировка переживает `>`: значение старой ячейки «переезжает» на новый адрес и при следующей выгрузке запишется туда | REQ-ML-005 | `store_keeps_lock_across_move` |
| 4 | ISA1 во время загрузки переключает ISA, после чего 0x4 — это `>`, а не EOT; загрузку завершит только ISA0 + EOT | не описано | `isa1_during_load_hides_eot` |

Пункт 3, скорее всего, дефект, а не намерение: копирование по REQ-ISA-BF-004 (`LOAD`, переход, `STORE`) работает и без него.

## 5. Найденные проблемы

### 5.1. `.` выводит значение не той ячейки — дефект RTL, противоречит OPEN-017

`MachineCtrl` на опкоде `5'h18` сразу поднимает `tx_vld` и не выдаёт `AP_COUT`. Константа `AP_COUT` объявлена, но нигде не используется. Без MemLock `tx_data_bcd` берётся из выходного регистра памяти, а после `>` он хранит **предыдущую** ячейку. Поэтому `>.` выводит не то. Если в модели убрать чтение перед выводом (то есть повторить RTL), `helloworld.bfk` печатает `Hello WWrld!!` вместо `Hello World!`.

TRS §18 закрывает OPEN-017 со словами «теперь используется». В текущем `MachineCtrl.sv` это не так.

Здесь модель RTL **не** повторяет: иначе она не прошла бы Hello World и была бы бесполезна как эталон. Она делает то, для чего в `ApLine` есть `OP_COUT`: читает ячейку при необходимости. Пошаговое сравнение поймает это место первым.

### 5.2. Переполнение счётчика циклов, вероятно, не останавливает машину — подозрение, в симуляторе не проверено

В `MachineCtrl` присваивание `state <= S_HALT` по `loop_overflow` стоит **перед** `case (state)`. В том же такте `IpLine` уже вернулся в `S_IDLE` с `insn_valid_q = 1` и `ready = 1`, поэтому ветка `S_FETCH_W` присваивает `state <= S_DECODE` позже. Последнее неблокирующее присваивание побеждает. Машина декодирует скобку, на которой прервалась промотка, выставляет `error_flag` и продолжает работу, хотя REQ-CNT-007 требует останова.

Модель останавливается, как требует TRS. Нужен направленный тест `MachineCtrl` на Icarus.

### 5.3. В пошаговом режиме пропуск цикла не выполняется — дефект RTL

`IpLine.halt_rq` подключён к `IsHalted`. При входе в останов с `ip_counted_q` IpLine делает шаг IP **без проверки промотки**. В режиме Step машина останавливается после каждой инструкции, поэтому `[` при нулевой ячейке не пропускает тело, а входит в него. То же случится, если нажать Halt сразу после скобки. Модель пошаговый режим панели не моделирует.

### 5.4. `generate_rom.py` теряет NOP

`if not encoded: continue` отбрасывает опкод 0 (`'N'`), потому что 0 ложно. Программа с `N` в RTL-прошивке окажется короче, чем в модели, и все адреса после первого `N` сдвинутся. Исправление: `if encoded is None`. Загрузчик модели `dpc::assemble()` NOP сохраняет (тест `loader_skips_comments_keeps_nop`).

### 5.5. Загрузка в Debug ISA не может передать `>`

EOT и `>` имеют один код 0x4, а EOT распознаётся по `{insn_mode, insn_in}`. После `SOT` машина остаётся в Debug ISA (OPEN-003), поэтому первый же `>` в загружаемой BF-программе завершит загрузку. Рабочий протокол сейчас такой: `ISA1`, программа, `ISA0`, `EOT`. При этом `ISA1`/`ISA0` попадут в память. Это надо учесть при решении OPEN-003 и в загрузчиках (REQ-LOAD-014).

## 7. Интеграция

- **CI** — только в репозитории bfutils (решение владельца): `.github/workflows/ci.yml`, gcc и clang, `cmake` → `ctest` → `test/test.sh`. Мёртвый `.travis.yml` удалён. `cmake_minimum_required` поднят с 3.1 до 3.10: CMake 4.x отказывается конфигурировать проекты с минимумом ниже 3.5. Ветка clang локально не проверялась, компилятора на узле нет.
- **Verilator-тестбенч** `rtl/tests/DekatronPC.sv/DekatronPC_tb.cpp` переведён на новый интерфейс. Шаг RTL — проход `MachineCtrl` через `S_DECODE` до `S_IDLE`/`S_HALT`. Сравниваются IRET, IP, AP, `tx_data_bcd`, LoopCount и вывод терминала. Символ CIN передаётся модели. В `run_tests.sh` добавлен `-GEN_EMULATOR=1`, без него IRET и LoopCount не выводятся. **Тестбенч не собирался**: полная сборка DekatronPC в Verilator тяжёлая. Проверен только синтаксис против заглушки `VDekatronPC.h`. Сравнение по-прежнему включается ключом `-s`, в `run_tests.sh` оно не включено: оно упадёт на §5.1.
