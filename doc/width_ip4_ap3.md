## 3. Влезают ли программы

- Из набора проекта: pi.bfk 636 операций, program 227, helloworld 111; максимальный AP при pi.bfk — 999 (загрузчик `0<{0<}` оборачивает AP до 999 и чистит 1000 ячеек). fractal.bfk (11 091 операций) в 10k не влезает, в CI его нет.
- Набор Brainfuck-100 (99 программ), модель dpcrun с `IP_SIZE = 10000`, `-a 999`, таймаут 15 с:
  - 64 программы дают тот же вывод, что при 5/5;
  - 24 программы не завершаются на обеих ширинах (ждут ввод или бесконечны), сравнить нельзя;
  - 11 расхождений/таймаутов в одну сторону — все в программах длиннее 9989 операций (hanoi-opt 45k, order 20k, oobrain 18k, mandel 11.4k, mandelbrot-huge 11.5k, bfbf 27k, awib 34k, Zozotez 36k, pi-digits 39k, Prime-multi 13k; LostKng 2.1 М);
  - то есть данных 1000 ячеек хватило всем завершающимся программам, которые влезают по длине; ограничением служит именно память программ. Из 99 программ 12 длиннее 10k.
- Оговорка: 24 зависающие программы короче 10k тоже не проверены на нехватку ячеек; для них нужен вход/лимит шагов.

## 4. Что пришлось менять

1. `parameters.sv`: `IP_DEKATRON_NUM = 4`, `AP_DEKATRON_NUM = 3`.
2. `Ram`: `BANK_DIGITS` по умолчанию 4 больше адреса из 3 разрядов (`$error` в симуляции, SELRANGE в lint): `BANK_DIGITS = min(D_NUM, 4)`. Физическая машина с BANK_DIGITS = 2 не затронута.
3. `AP_TOP_VALUE` по умолчанию — 5-разрядная константа, усекается: сделана от `AP_DEKATRON_NUM`.
4. Эмулятор (`MS6205`, `io_key_display_block`) читает адреса с битами [19:16] — дополнены нулями до 5 разрядов (только индикация FPGA).
5. Тесты: `DekatronPC_tb.sv` ждал IP после включения `99990` — теперь `{N−1 девяток, 0}`; `DekatronPC_tb.cpp`: ширины `BcdToInt` 4/3 и `apTop = 999`; `synth_sim.sh:154`: `HARD_RST_D_CNT=4` → 3 (иначе IpLine-нетлист падает на проверке параметра, а не по логике).
6. Golden-модель bfutils (`dpcrun.h`): `IP_SIZE = 10000`, `BOOT_BASE = 9990`; в релизе — см. §5.

Вывод: тесты и синтез согласуются, регрессий нет; ширина 4/3 экономит ≈ 74–81 лампы (≈ 8 %), включая три A110.

## 5. Принято в релиз (TRS v0.63, 2026-11-11)

Владелец: в релиз идут IP = 4 и AP = 3, к этой ширине делается ферритовая память (10 000 × 4 бит программ, 1000 × 10 бит данных). Правки §4 внесены в дерево (справочный патч удалён), плюс:

- `AP_TOP_VALUE` по умолчанию — `{AP_DEKATRON_NUM{9}}` = 999 (параметр не подключён, AP идёт по кругу), комментарии 99990 → 9990 в RTL и тестах; `IpLine_tb` — адрес загрузчика и модель памяти от `IP_DEKATRON_NUM` (ушло предупреждение о ширине порта), `ApLine_tb` — `dbg_addr` по ширине порта.
- bfutils `dpcrun` (PR #5, слит; подмодуль на `81a9427`): `IP_SIZE = 10000`, `BOOT_BASE = 9990`, `AP_SIZE = 1000`/`AP_TOP = 999` вместо `AP_TOP_BF = 29999`, `-a` принимает только 1..999, трасса `-s` печатает IP 4 и AP 3 разрядами; тесты и README. `test_dpcrun`: 46 тестов, 0 отказов.
- Веб-симулятор (`web/`): порт текущего dpcrun — ISA16 без режимов (было ISA0/ISA1), 12 декатронов (IP 4, Loop 2, AP 3, Data 3), ПЗУ — настоящий `bootloader.bfk` (`0<{0<}NNNS`), он и очищает память данных; переполнение Loop останавливает без останова (TC-N2); признак «влезает в 4-2-3-3» для Brainfuck-100 считает `build_bf100.py` (78 из 100). Подробно — `doc/web_simulator.md` §1–2.
- AGENTS.md: инварианты ширины, загрузчика и памяти.
