2. What the project is
A Brainfuck computer built from A110 dekatrons and vacuum tubes, plus an FPGA emulator (DE0-Nano-SoC, Cyclone V) that stands in for tube blocks that aren't built yet.
- Authenticity (REQ-AUTH-*): no silicon semiconductors in the real machine's compute path; germanium diodes allowed only in rectifiers (power) and ferrite-memory support; BCD codecs are tubes (owner, 2026-10-08, REQ-AUTH-002). FPGA is a temporary dev tool only. UART/terminals/loaders are external and may be non-tube.
- Priorities (REQ-SCOPE-003): RTL, then test stand, then tube modules, then measurements/liberty. The P&R tool is a separate project that takes netlist/liberty/connector requirements from the TRS (section 17). P&R decisions of 2026-10-09 (REQ-PR-011..019) shape synthesis output. The netlist stays hierarchical: a submodule with a board type, such as DekatronModule, is one board. A P&R block is a cabinet of 3–5 baskets. Inter-block wires go through HD-68 connectors, and RTL should group them into one wire structure per connector (REQ-PR-019). The review is doc/webui_review.md on branch webui (PR #28).

3. Architecture facts (don't break these)
- Four reversible BCD dekatron counters, Harvard architecture. Widths come from rtl/parameters.sv:
  - IP: 5 dekatrons, 0–99999 (100k instructions). The old PDF's 6 dekatrons / 1M is obsolete (REQ-ARCH-009).
  - Loop: 2 dekatrons, 0–99 by TRS v0.9 (REQ-CNT-002, chosen on the Brainfuck-100 set: max nesting during scan is 67); rtl/parameters.sv has LOOP_DEKATRON_NUM = 2. Overflow is a hardware error: it must abort the loop scan and halt the machine, or the machine hangs (REQ-CNT-007).
  - AP: 5 dekatrons physically, BF limit 0–29999. The choice between 29999 and 99999 stays a parameter until RTL freeze (OPEN-001). The current RTL runs in the 99999 mode: ApLine's AP counter has no top limit (TOP_LIMIT_MODE = 0, AP_TOP_VALUE is not connected), so AP wraps 0 ↔ 99999; DekatronPC_tb.cpp builds dpcrun with apTop = 99999 to match (-a overrides it).
  - Data: 3 dekatrons, 0–255, 12-bit BCD out.
- Program memory: 100k × 4-bit opcodes. Data memory: 100k × 10-bit cells in the current RTL (owner, 2026-10-08; 30k if OPEN-001 goes to 29999) encoded {hundreds[1:0], tens[3:0], ones[3:0]}; on read, the top 2 hundreds bits come back as 2'b00.
- Memory is a recursive bank tree (bank of 10×10 = 2 dekatrons, then groups of 10, and so on). Addresses are raw BCD tetrads compared directly, with no BCD-to-binary arithmetic; tetrads A..F raise err. The bootloader is the top 10×10 bank, 99900–99999, write-protected, overlaid with ovl_hit/ovl_data inputs.
- OPEN-015 (closed in TRS v0.8): the bank size is the BANK_DIGITS parameter, 2 (10×10) for the real machine and 4 (100×100) for the FPGA; no flat memory is needed (about 80 memory blocks).
- Clocks: Clk = 1 MHz CPU clock; hsClk = 10 MHz models dekatron pulse timing (emulator only, not in the real machine). Everything else is emulator/peripheral.

4. ISA (opcodes are near-final: never renumber existing codes)
Decode on the pair {insn_mode, insn}. All 32 combinations must be covered. Undefined or reserved opcodes act as NOP and never raise an error.
| Op | Debug ISA (mode 0) | Brainfuck ISA (mode 1) |
|---|---|---|
| 0x0 | NOP | NOP |
| 0x1 | HALT | HALT |
| 0x2 | BELL | INC + |
| 0x3 | reserved (NOP) | DEC - |
| 0x4 | EOT (end of load; NOP outside load mode) | AINC > |
| 0x5 | SOT (start of load) | ADEC < |
| 0x6 | LABEG { (skip if AP==0) | LBEG [ (skip if data==0) |
| 0x7 | LAEND } (repeat if AP!=0) | LEND ] (repeat if data!=0) |
| 0x8 | CLRL | COUT . |
| 0x9 | CLRI (IP and MemLock) | CIN , |
| 0xA | CLRD | CLRD [-] (sets MemLock) |
| 0xB | CLRA (AP and MemLock) | CLRML (flush and clear MemLock) |
| 0xC | HRST | LOAD |
| 0xD | SRST | STORE |
| 0xE | ISA0 (to Debug) | ISA0 |
| 0xF | ISA1 (to BF) | ISA1 |
- The table above matches MachineCtrl.sv, which decodes literal {mode, opcode} values. rtl/DekatronPC/insnValues.sv is stale: it has no BELL and no 0x0C, and it names 0x0D INSN_RST. Only the old InsnDecoder uses it.
- Debug loops test AP; BF loops test Data. Bracket opcodes 0x6/0x7 are the same in both ISAs, so a single detector is enough.
- Hard Reset: IP=99900, AP/Data/Loop=0, MemLock cleared, Debug ISA; runs the bootloader if RunOnHardRst is set. Soft Reset: all counters 0, MemLock cleared, BF ISA; runs from 0 if RunOnSoftRst is set.
- SOT/EOT: after SOT the machine accepts opcodes via InsnIn/InsnInValid/InsnInReady and auto-increments IP. With SoftRstOnEOT set, EOT triggers a Soft Reset.
- IpLine only ever sees opcodes, never ASCII symbols. Conversion belongs to the loader, and any verification model must follow the same rule (REQ-IPV2-005).

5. RTL design rules
- Handshake: Valid/Ready everywhere above the dekatron, and ready must not depend on valid. APB was tried and rejected in v0.7. Don't reintroduce single-cycle pulse Request/Ready.
- Terminal RX (REQ-UART-008): the sender holds rx_data_bcd until rx_vld & rx_rdy. DekatronPC.rx_rdy comes from MachineCtrl in the cycle ApLine finishes CIN, and ApLine loads the Data counter straight from rx_data_bcd (no rx_q). The Emulator holds the UART/consul byte in its own receive buffer.
- Dekatron physics (REQ-DEK-012/015/016): the tube has no valid/ready/busy. It reacts to pulses of a given length regardless of its state. A discharge can't rest on a guide cathode: it falls back from guide A and forward from guide B. A reading is valid only on a main cathode with no stimulus. Since TRS v0.10 there is no Valid signal at all (DekatronModule.Valid, the OR10_X7 cell and DekatronCounter.out_valid are gone): DekatronCounter derives ready from known durations. A step fits in one clk; set/set_zero and a rising soft_rst/hard_rst start the writeTimer window, and ready returns when the window ends and the reset line is low. All discipline lives in DekatronCounter.
- Dekatron stack under rtl/DekatronPC/Dekatron/:
  - DekatronTubeV2: a 30-bit one-hot ring model, not an FSM.
  - DekatronTubeDelay: the same ring model with no hsClk port; moves, writes and resets are inertial #N delays in ns (HS_NS = 100 per *_HS unit). The position of the discharge is part of each move request, so two moves in the same direction don't merge. Selected by `define DEKATRON_DELAY_MODEL in DekatronModule. It is not in DPC.files (Icarus only; Verilator/Quartus never see it). The same define switches Impulse, OneShot (new HS_NS parameter, default 100), DekatronPhaseGen and the DekatronPulseSender check to delays through `ifdef/`else branches inside those modules (owner: no new modules, no port changes). DekatronCounter then uses no hs_clk at all: Counter_tb/Dekatron_tb hold hsClk at 0 under the define. RstTimeRelay has the same branch, and DekatronPC routes a local tclk (hsClk, or 1'b0 under the define), so the whole DekatronPC runs with hsClk held at 0 (DekatronPC_tb generates Clk itself under the define). The hsClk ports stay because Appendix B is frozen (doc/dekatron_delay_model.md §8–9). Testbenches drive DUT inputs with non-blocking assignments after a clock edge: a blocking one races the DUT on that edge (found in DekatronPC_tb).
  - DekatronModule wraps it with gate-level codecs. Codecs are placed only for WRITE/READ, and sub-blocks stay separate instances so P&R can swap them for tube cells.
  - DekatronCounter is the first Valid/Ready level.
  - DekatronPhaseGen splits the clock into thirds (guide A, guide B, fall) so the tube can count every cycle at 1 MHz.
  - DekatronPulseSender is pure combinational logic, one per counter together with the phase generator (REQ-PULSE-007): it drives the guide buses GuideA/GuideB, and each DekatronModule passes them to its guides through two GUIDE_EN_J2 cells, one per guide (a liberty cell: one J2 tube, a pentode with two control grids, guide pulse on one and En on the other; no function, so ABC never uses it) when its En (the carry chain) is set.
  - A counter with WRITE=0, TOP_LIMIT_MODE=0 and HARD_RST_D_CNT=0 (Loop, AP) uses one busy_q trigger instead of the FSM (ZERO_ONLY in DekatronCounter).
- Timing parameters must be explicit: GUIDE_STEP_HS, FALL_STEP_HS, GUIDE_MAX_HS, WRITE_MIN_HS, RESET_MIN_HS. The current values are estimates until they're calibrated on hardware (OPEN-013/014). Default phase split is 3/3/4 hs (PHASE1/PHASE2/fall): the fall window must be strictly longer than FALL_STEP_HS, so the discharge lands before the next clk edge (with 3/4/3 it landed on the edge). The write window must be longer than one count cycle. Both are checked at compile time.
- soft_rst/hard_rst are physical lines. An external time relay holds them, so don't add stretch logic in RTL. rst_n resets logic only and never moves a discharge. MachineCtrl must react to reset lines from the panel, not only to its own HRST/SRST requests.
- ApLine uses lazy reads (about 36% fewer memory accesses on pi.bfk). The memory's rd_data register holds the last touched cell (write-through), so ApLine keeps only lock/mem_here and never stores a copy of the cell. MemLock (lock_q) is the only ownership flag (owner, 2026-10-08; there is no dirty): data can't change without lock (load first), and the address can't change or CLRML finish with lock set without a flush, which clears lock. STORE writes and keeps lock, so the next AP step or CLRML writes the same value again (doc/memlock_single_flag.md). Before [ or ] in BF mode MachineCtrl issues TEST; in Debug mode it doesn't.
- Decode once (REQ-APV2-008, REQ-IPV2-008): ApLine's op is the opcode itself, not re-encoded (ApLine decodes it, direction = op[0]); IpLine gets a single clr bit and picks CLRI/CLRL from insn[0]. IpLine has no opcode register: insn is the program memory's rd_data, which changes only on an access (Ram and ferrite memory both behave this way). EOT is never written to memory, so IpLine reports it with the 1-bit insn_eot (owner decision); during loading the opcode is written straight from insn_in in the handshake cycle.
- Prefetch (REQ-PERF-003, owner decision): MachineCtrl raises ip_valid together with ap_valid in S_EXEC for every ApLine op except TEST (brackets); CIN doesn't prefetch. rd_data then changes before ApLine finishes, so the opcode is latched in MachineCtrl's op_q (written in S_FETCH_W and in the instruction's last cycle) and all decode after the fetch uses op_q; ApLine's op is ap_op = {insn_mode, op_q}. After S_WAIT/S_COUT the FSM goes straight to S_DECODE. IP is then one ahead: on halt, IpLine's ip_ahead input suppresses the usual halt step and the instruction is re-read on resume. DekatronPC_tb.cpp counts an S_DECODE entered from S_WAIT/S_COUT as a retire with IP = model IP + 1. CLRL/CLRI must not prefetch (IpLine reads insn[0] at accept), nor may brackets (IpLine decides the scan from the live insn at accept).
- MemLock:
  - Set before the first +/-.
  - Flushed on >/< before the AP step.
  - LOAD/STORE don't touch it.
  - CLRD sets it; without that, [-] doesn't clear the cell.
  - CLRML flushes the counter to memory, then clears MemLock.
- Loop scan runs entirely inside IpLine and stops on the matching bracket, not after it.
- Relay logic (REQ-MOD-011): logic controlled only by panel switches (EN/MUX) is built from 2CO relays, not tubes: RelayMux/RelayEn in rtl/Logic/Relay.sv (keep_hierarchy, cell RELAY_2CO in vtube_cells.lib, 0 tubes, no function so ABC never uses it). A coil is driven only by a user switch, never by fast or clocked logic; contacts may pass any signal. Use a relay only where it removes tubes (measure over several ABC seeds, doc/tube_count_reduction.md §15): EchoMode and SoftRstOnEOT stay on tubes.
- FSM state registers that Yosys extracts carry (* fsm_encoding = "binary" *): one-hot recoding costs about 219 tubes on 7-tube triggers (doc/tube_count_reduction.md §17). MachineCtrl's state is an output port and isn't extracted.
- Synthesizable constructs only. No X-masking tricks. FPGA-specific primitives go only in the Emulator layer, above DekatronPC. The code style is SystemVerilog; BcdToBin.v/BinToBcd.v are legacy Verilog-95.
- Combinational loops: treat Verilator UNOPTFLAT as an error and fix it structurally, never with lint_off. A ripple written bit-by-bit into a vector that is also read counts as a false loop: use locals inside always_comb. A model check isn't a simulator check: Python cycle models can't see zero-delay loops (REQ-VER-029/031/032).
- Emulator to DekatronPC interface: frozen by TRS Appendix B (instantiated in rtl/Emulator/Emulator.sv). Any change is a breaking change: update the TRS and io_key_display_block/MS6205/Sequencer together.

7. Build and test (CI: .github/workflows/docker-image.yml, all inside the Docker image from ./Dockerfile)
- cocotb regression: cd tb && make regression (or a single target: make test_compare SIM=icarus). Module tests run on Icarus; DPC/Emulator integration runs on Verilator. Needs cocotb>=2.0 + pyuvm + pytest (local venv: ~/.venvs/dekatronpc). Never install cocotb-coverage next to it: it pins cocotb<2.
- RTL simulation: cd rtl/run && ./run_tests.sh -t (Icarus tests, then DekatronPC_tb.cpp in Verilator with -s against dpcrun on helloworld and program.bfk; exit code is the verdict). CI's Docker image has Icarus 12: no break/continue in testbenches. A local Icarus 13 won't catch that, so build v12_0 to reproduce CI (doc/ci_sim_check.md).
- Single Icarus tests: cd rtl/run && ./emul <Test> (Dekatron, Counter, IpLine, ApLine, MachineCtrl, ...). IpLine_tb runs whatever is in rtl/firmware.hex: run_tests.sh -t writes looptest.bfk there, but run_tests.sh -d leaves pi.bfk, and IpLine then fails with "did not halt within 2000 instructions" and a VCD of many GB. Regenerate looptest first: python3 generate_rom.py -f ../programs/looptest.bfk -o ../firmware.hex --hex.
- Netlist simulation (REQ-VER-025): cd rtl/run && ./synth_sim.sh [-n] [test ...] (or run_tests.sh -g). Synthesizes each DUT with synt_dpc.tcl -p (its testbench parameters) -bb (DekatronTubeV2, OneShot, Impulse, RstTimeRelay, Ram, IpMemory stay black boxes and come back from RTL; OneShot/Impulse are special tube circuits by owner decision, outside the ABC tube count like the dekatrons), then runs the unchanged Icarus testbench on the netlist + rtl/vtube/vtube_cells.v (keep it one to one with vtube_cells.lib; synth_sim_prep.py checks). Output in rtl/run/synth_sim/, about 2.5 min for all. All runs, DekatronPC included, pass, and the CI job synth_sim is a required check (doc/synth_sim.md). The netlist does not mask X like RTL does (reconvergent paths), and combinational outputs such as IsHalted can pulse for zero time: testbenches sample DUT outputs on a clock edge, never with wait()/@(posedge) on a decoded line.
- Delay-based tube model (REQ-DEK-010): ./run_tests.sh -d runs all Icarus tests plus pi.bfk with DekatronTubeDelay, writing to rtl/run/delay/. ./synth_sim.sh -d [test ...] does the same on netlists (synt_dpc.tcl -D DEKATRON_DELAY_MODEL), writing to rtl/run/synth_sim_delay/. The synth_sim test Pi runs pi.bfk on the DekatronPC netlist and is not in the default set. CI jobs: sim_delay, synth_sim_delay. DekatronPC_tb runs hsClk at a real 10 MHz (#0.5 at 100 ns): the delay model works in absolute time.
- Tube cell delays (doc/vtube_sdf_timing.md): ./synth_sim.sh -t [-c NS] [test ...] (implies -d, output in rtl/run/synth_sim_timing/) annotates the netlist with the delays of rtl/vtube/vtube_timing.json (the only place for cell timing: 150 ns per arc, triggers setup/hold 150/150 ns) through SDF (rtl/run/vtube_sdf.py, iverilog -gspecify, one SDF per netlist module: Icarus can't resolve escaped names like \dek[0].dModule in SDF paths). Icarus ignores $setuphold, so rtl/vtube/vtube_timing_check.v checks every trigger instead. -c sets the Clk period of Dekatron/Counter/DekatronPC_tb (`CLK_NS, default 1000). Files are capped at 2 GB under -t. Status: DekatronCounter fails at any period, because the phase windows (absolute time from Clk ↑) close before step_f arrives; the fix is an owner decision.
- Synthesis: cd rtl/run && ./run_tests.sh -s (Yosys with -define SYNTH=1 and rtl/vtube/vtube_cells.lib; Ram is stubbed under SYNTH because the recursive RamGroup loops hierarchy -check, so the tube count excludes memory). dpc_stat.py prints tubes and relays per block; it needs the liberty parser from rtl/run/.venv. ABC results drift by up to ±10 tubes between runs, so compare small changes over several &deepsyn seeds.
- FPGA bitstream: cd rtl/run && ./build_fpga.sh [elab|syn|compile|program] [-p] [--rbf] [-n]. Generates rtl/quartus_build/ (gitignored) from quartus/Emulator.qsf (pins, device) plus DPC.files/Emul.files (the qsf's own file list is stale), regenerates the firmware hex, runs Quartus (native, or the Windows install under WSL, found in /mnt/c/intelFPGA_lite). Programs JTAG device 2 (FPGA after HPS). See doc/fpga_build.md. CI: .github/workflows/fpga.yml (PR: elab; push to master/manual: full compile, .sof/.rbf artifacts) runs in the community image chriz2600/quartus-lite:23.1.1-1 pinned by digest (Altera blocks scripted installer downloads); if the image fails, the fallback is a self-hosted runner on the owner's server (doc/fpga_build.md §6).
- Resource note (§0): full-design Verilator builds and Quartus runs are heavy. Ask before starting them on small nodes and prefer single tb targets.
