# AGENTS.md

A Brainfuck computer built from A110 dekatrons and vacuum tubes, plus an FPGA emulator (DE0-Nano-SoC, Cyclone V) that stands in for tube blocks that aren't built yet. This file holds only the rules and invariants an agent needs in order not to break things. Everything else lives in TRS.md and the reports in doc/.

## 1. Working rules (from the project owner)

- **Record every investigation as Markdown**: a new report in doc/, or an extension of the report next to the RTL it covers. Don't leave results only in chat.
- **Append to history.md every session**: one bullet of 1–2 sentences saying what was done.
- **Keep the TRS current.** TRS.md (repo root, Russian) is the source of truth. Every requirement has an ID (REQ-\*, OPEN-\*) and a status (TODO / In Progress / In Review / Assumption / Done / Rejected). Cite IDs in commits, reports and code comments. When work changes a status or a fact, update the TRS under a new version tag (e.g. [v0.11]) in its header and §1. TRS §19 (checklist), §21 (Definition of Done) and §22 (next actions) are the live to-do list. Update this file only when a rule or invariant changes.
- **Ask when unsure** about an idea, interpretation or direction, and always for the OPEN-\* items (TRS §18).
- **Save machine resources.** Prefer light tools (single Icarus tests, Python models, `verilator --lint-only`). Ask before heavy jobs: full DekatronPC/Emulator Verilator builds, `make regression`, Quartus, full Yosys synthesis.
- **On a powerful PC (≥ 16 threads and ≥ 24 GB RAM; check with `nproc` and `free -g`), the heavy jobs are mandatory, not optional.** Before calling a change done, run every test and the full synthesis, the same set CI runs: `cd tb && make regression`, `./run_tests.sh -t`, `./run_tests.sh -d`, `./run_tests.sh -s`, `./synth_sim.sh`, and for any change that can move the tube count, `./synth_seeds.sh -s "0 1 2 3" IpLine ApLine MachineCtrl`. Quartus is still asked for. Report each result in the session's report and in history.md.
- **Block diagrams**: SCHEMES.md and img/schemes/ are generated by `python3 tools/schemes/build.py`. Edit the sheets there, never the output, and redraw them when the RTL they show changes.
- **Paths in the TRS can be stale** (e.g. the TRS says Ram.sv, the file is rtl/DekatronPC/RAM.sv). Check the tree.

## 2. Hard constraints

- **Authenticity (REQ-AUTH-\*)**: no silicon semiconductors in the real machine's compute path. Germanium diodes are allowed only in rectifiers and ferrite-memory support. BCD codecs are tubes. The FPGA is a temporary dev tool. UART, terminals and loaders are external and may be non-tube.
- **Priorities (REQ-SCOPE-003)**: RTL first, then the test stand, then tube modules, then measurements/liberty.
- **P&R (TRS §17, REQ-PR-011..019)**: the netlist stays hierarchical, and a submodule with a board type (e.g. DekatronModule) is one board. Inter-block wires go through HD-68 connectors, and the RTL groups them into one wire structure per connector (REQ-PR-019).
- **Emulator ↔ DekatronPC interface** is frozen by TRS Appendix B. Any change is a breaking change: update the TRS and io_key_display_block/MS6205/Sequencer together.

## 3. Architecture invariants

- Harvard architecture with four reversible BCD dekatron counters (widths in rtl/parameters.sv):
  - IP: 5 dekatrons, 0–99999.
  - Loop: 2 dekatrons, 0–99. Overflow is a hardware error that must abort the scan and halt the machine (REQ-CNT-007).
  - AP: 5 dekatrons. The RTL wraps 0 ↔ 99999 (no top limit); the 29999 option is OPEN-001.
  - Data: 3 dekatrons, 0–255.
- **Memory**: program memory is 100k × 4-bit opcodes; data memory is 100k × 10-bit cells {hundreds[1:0], tens, ones}. It is a recursive bank tree with BANK_DIGITS = 2 for the real machine and 4 for the FPGA. Addresses are BCD tetrads compared directly, with no binary arithmetic; tetrads A..F raise err. **Value buses are BCD active-low** (TC-O3): counter outputs come from BinToBcdN (NOR, no output inverters), so memory addresses and data, the terminal buses and the emulator status ports carry inverted tetrads (zero = 4'hF). The memories invert on their ports (ADDR_ACTIVE_LOW / DATA_ACTIVE_LOW) and keep the direct code inside; the emulator inverts at the DekatronPC instance in Emulator.sv; testbenches compare in the direct code. The bootloader is the top decade, 99990–99999: write-protected, with the ovl_hit/ovl_data overlay.
- **Clocks**: hsClk exists only for the clocked dekatron model (DekatronTubeV2), so that the complex model runs without delays on the FPGA and in Verilator/Icarus RTL runs. It is always 10 × Clk (HSCLK_DIV = 10; one *_HS unit = Clk/10). Clk = 100 kHz by default (build macro DEKATRON_CLK_NS in rtl/parameters.sv → CLK_PERIOD_NS, HSCLK_NS for testbench clocks). Synthesis and every delay simulation have no hsClk signal at all (TRS v0.25).

### ISA16 (TRS v0.42, doc/isa16.md; never renumber these codes)

One 4-bit instruction set: there is no insn_mode and no ISA switch. Decode on the opcode alone; all 16 codes are defined. MachineCtrl.sv is the reference; rtl/DekatronPC/insnValues.sv is stale (only the old InsnDecoder uses it).

| Op | Instruction | Op | Instruction |
|---|---|---|---|
| 0x0 | NOP | 0x8 | COUT . |
| 0x1 | HALT | 0x9 | CIN , |
| 0x2 | INC + | 0xA | CLRD [-] (sets MemLock) |
| 0x3 | DEC - | 0xB | LD: SOT; in the load stream EOT (not stored) |
| 0x4 | AINC > | 0xC | CLRA (AP; a locked cell is flushed first) |
| 0x5 | ADEC < | 0xD | MemLock (sets the MemLock flag without a load: cell := data counter) |
| 0x6 | LBEG [ (skip if data==0) | 0xE | LABEG { (skip if AP==0) |
| 0x7 | LEND ] (repeat if data!=0) | 0xF | LAEND } (repeat if AP!=0) |

- Brackets are x11x: bit 0 open/close, bit 3 what is tested (0 the cell, 1 AP). The scan counts [ ] and { } together, so the two kinds must nest properly with each other; { } exist for the bootloader.
- **Hard Reset**: IP = 99990; AP, Data and Loop = 0; MemLock cleared. **Soft Reset**: all counters 0, MemLock cleared. Resets come only from the panel and SoftRstOnEOT (EOT triggers a Soft Reset); the Loop overflow is cleared only by a reset.
- **Bootloader** (programs/bootloader.bfk): `0<{0<}` clears the data memory, LD at 99999 loads from address 0. Program files end with `HE` (HALT, LD as EOT).
- **IpLine sees only opcodes**, never ASCII. Conversion belongs to the loader, and verification models follow the same rule (REQ-IPV2-005).
- **The loop scan** runs entirely inside IpLine and stops on the matching bracket, not after it.

## 4. RTL rules

- **Handshake**: Valid/Ready everywhere above the dekatron, and ready must not depend on valid. No APB and no single-cycle Request/Ready pulses.
- **Dekatron physics (REQ-DEK-\*)**: the tube has no valid/ready/busy and no Valid signal. DekatronCounter derives ready from known durations, and all timing discipline lives there. Every counter operation (step, write, set_zero, edge wrap) completes in its accept cycle: no FSM, no write window, ready drops only on the reset lines (REQ-CNT-V2-009). The cathode read lines are readable at all times but valid only on the Clk edge that ends the operation. A discharge can't rest on a guide cathode. Guide A and guide B pulses must touch or overlap, never leave a gap (REQ-PULSE-008): Phase2 is started by the fall of Phase1, not by gates. Dekatrons light at random on power-up (sim: `define DEKATRON_RANDOM_INIT`), and only the reset lines fix that (REQ-DEK-017). Timing parameters (GUIDE_STEP_HS, FALL_STEP_HS, GUIDE_MAX_HS, WRITE_MIN_HS, RESET_MIN_HS, phase split 3/3/4) are explicit and checked at compile time. They stay estimates until calibrated on hardware (OPEN-013/014). Design notes: rtl/DekatronPC/Dekatron/DekatronCounter.md. In the tube machine (delay model) the carry enables are one LATCH_J2N16 per decade, open in the command window CmdWin (Clk edge → phase start) and closed through the phases and the fall; only a write may move a discharge inside CmdWin (doc/tube_count_1000.md §3).
- **Board boundaries**: codecs and gate cells stay separate instances so P&R can swap them for tube cells. GUIDE_EN_J2 and RELAY_2CO are liberty cells with no function, so ABC never uses them.
- **Reset lines**: soft_rst/hard_rst are physical lines held by an external time relay, so add no stretch logic. rst_n is not a reset of its own: low rst_n holds hard_rst in RstTimeRelay (as power-on), so rst_n = hard_rst | soft_rst. No glue trigger of IpLine/ApLine/MachineCtrl has rst_n; each is reset by soft_rst/hard_rst synchronously or written before it is read. rst_n stays only as the model reset of the RC delay elements and the emulator's iret; block testbenches pulse a reset line after rst_n (REQ-REF-011, TC-O5). MachineCtrl reacts to the reset lines themselves (panel or its own SoftRstOnEOT request).
- **MemLock** (lock_q) is ApLine's only ownership flag (doc/memlock_single_flag.md):
  - Data can't change without lock: load first.
  - The address can't change with lock set unless the cell is flushed first; the flush clears lock.
  - CLRD sets lock.
  - The MemLock instruction (0xD) only sets lock: the counter takes the current cell with its old value, and the next address change writes it there (copy).
  - The memory's rd_data holds the last touched cell, so ApLine never keeps its own copy.
- **Decode once**: ApLine gets the opcode itself; IpLine gets only "next instruction" requests (no clr). IpLine has no opcode register (insn is the memory's rd_data). EOT is never written to memory and is reported as insn_eot.
- **Prefetch** (doc/prefetch_p3.md): MachineCtrl fetches the next opcode during an ApLine op, so all decode after the fetch uses op_q. CIN and brackets must not prefetch. On halt, ip_ahead suppresses the halt step. MachineCtrl issues TEST before [ and ], never before { }.
- **Terminal RX (REQ-UART-008)**: the sender holds rx_data_bcd until rx_vld & rx_rdy, and ApLine loads Data straight from it.
- **No relays in logic** (TRS v0.43, REQ-MOD-011 rejected): panel switches go into tube logic; a separate relay board is not worth a few tubes. RELAY_2CO stays in the liberty unused.
- **Yosys FSMs**: state registers carry (\* fsm_encoding = "binary" \*). "none" (codes as written) passes the zero-delay checks but breaks `synth_sim.sh -t` (doc/isa16.md §6.1): any encoding change must pass the tube-delay netlist.
- **Code**: synthesizable SystemVerilog only, with no X-masking tricks. FPGA primitives go only in the Emulator layer.
- **Combinational loops**: Verilator UNOPTFLAT is an error. Fix it structurally, never with lint_off. A ripple written bit by bit into a vector that is also read counts as a loop: use locals in always_comb. Python models can't see zero-delay loops, so they don't replace a simulator.
- **Delay model** (`define DEKATRON_DELAY_MODEL; DekatronTubeDelay is Icarus only and not in DPC.files) is the tube machine: synthesis always uses it (synt_dpc.tcl defines it and reads DekatronTubeDelay), and so do netlist sims and `run_tests.sh -d`. Under the define no module has an hsClk/hs_clk port, and OneShot/Impulse have no Clk port. All durations are in ns: the DEKATRON_*_NS macros in rtl/parameters.sv (guide/fall step, write/reset, phase delay/widths, edge pulse). The *_HS parameters belong to the clocked model only (doc/dekatron_delay_model.md, doc/dekatron_counter_single_cycle.md §7).

## 5. Repo map

- rtl/DekatronPC/: the core (DekatronPC, MachineCtrl, IpLine, ApLine, IpMemory, RAM, De0Nano). Its Dekatron/ subfolder holds the dekatron stack: TubeV2/TubeDelay → Module → Counter, PhaseGen, PulseSender.
- rtl/Emulator/: FPGA-only layer (keyboard, MS6205, IN-12, FirmwareLoader, io_register_block, legacy consul). Notes: rtl/DekatronPC/emulator_inspection.md.
- rtl/Logic/, rtl/Functions/: primitives and codecs.
- rtl/uart/: UART at 110 baud, 7N1.
- sch/logic/: tube logic cells, one folder per cell (`<CELL>.kicad_sch`, `<CELL>_tb.kicad_pro/.kicad_sch`, README.md cell page, img/; index in sch/logic/README.md, old sketches in legacy/), and the cell library: liberty vtube_cells.lib, models vtube_cells.v/.sp, timing vtube_timing.json, vtube_timing_check.v.
- rtl/programs/: .bfk programs and the bootloader.
- rtl/run/: scripts.
- rtl/tests/: Icarus/Verilator testbenches.
- tb/: cocotb + pyuvm (see tb/README.md).
- rtl/[DEPRECATED]/: don't touch.
- Old blocks still in use and due for removal (TRS 19.4): Dekatron.sv, DekatronPulseAllow, DekatronCarrySignal, RsLatch, InsnDecoder, BcdToBinEnc.
- bfutils/ is a git submodule. Its dpcrun is the C++ golden model; it mirrors the RTL as-is and is linked into DekatronPC_tb.cpp for step-by-step comparison. Change the model there, not here (`git submodule update --init`). The Brainfuck-100 set (bfutils/programs/bf100/) is the yardstick for any counter-width change (REQ-ARCH-011).
- sch/stand/: KiCad project of the test-stand PSU.
- doc/: reference literature and investigation reports.

## 6. Build and test

CI is .github/workflows/*.yml and runs inside the Docker image from ./Dockerfile.

- `cd rtl/run && ./emul <Test>`: a single Icarus test (Dekatron, Counter, IpLine, ApLine, MachineCtrl, …).
- `./run_tests.sh -t`: Icarus tests, then DekatronPC_tb in Verilator, compared with dpcrun step by step on helloworld, program.bfk and pi.bfk.
- `./run_tests.sh -d`: the same flow with the delay model.
- `./run_tests.sh -s`: Yosys synthesis with the tube count, by tube type and with the dekatrons (A110) on a line of their own; the dekatron module is counted through the cells WRCH_N16 / RDD_X7 / GLIFT_N16. dpc_stat.py needs the liberty parser: run_tests.sh and synth_seeds.sh take rtl/run/.venv, else /var/venv (CI). ABC drifts by ±10 tubes, so compare small changes over several seeds: `./synth_seeds.sh -s "0 1 2 3" IpLine ApLine MachineCtrl`. Synthesis keeps only boards and boxes (DekatronModule, relays, IpLine/ApLine/MachineCtrl); counters are flattened into their block.
- `./synth_sim.sh [-d] [-t [-c NS]] [test…]`: netlist simulation (doc/synth_sim.md, doc/vtube_sdf_timing.md). Keep sch/logic/vtube_cells.v one to one with vtube_cells.lib. Cell timing lives only in sch/logic/vtube_timing.json.
- `./build_fpga.sh [elab|syn|compile|program]`: Quartus build (doc/fpga_build.md). The file list in rtl/quartus/ is stale.
- `cd tb && make <target> SIM=icarus`: cocotb (needs cocotb ≥ 2.0, pyuvm and pytest; venv ~/.venvs/dekatronpc). Never install cocotb-coverage: it pins cocotb < 2.

Gotchas:
- CI uses **Icarus 12**, which has no break/continue in testbenches. A local Icarus 13 won't catch this (doc/ci_sim_check.md).
- **Netlist with tube delays** (`synth_sim.sh -t`) needs the phase start delay (REQ-PULSE-009; `-o`, 3300 ns under `-t`) and guide phases of 600 ns (`-w`), the same as `vtube_sta.sh`. The default Clk period is 10 µs (`-c`). Counter_tb drops its IP-like counter on netlists (`NETLIST_SIM`). doc/vtube_sdf_timing.md §3.3–3.6.
- **IpLine_tb** runs whatever is in rtl/firmware.hex, and after `-d` that is pi.bfk, which produces a multi-GB VCD. Regenerate first: `python3 generate_rom.py -f ../programs/looptest.bfk -o ../firmware.hex --hex`.
- **Testbench timing**: testbenches drive DUT inputs with non-blocking assignments after a clock edge. They sample DUT outputs on a clock edge, never with wait() on a decoded line: netlist outputs can pulse for zero time, and the netlist doesn't mask X.

## 7. Open decisions (ask, don't decide)

The full list is in TRS §18. The ones most often hit:
- OPEN-001: AP limit.
- OPEN-007: BELL behaviour (only the automatic bells; there is no BELL opcode since v0.42).
